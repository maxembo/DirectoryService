# DirectoryService — общие инструкции агенту

Эти правила действуют для всего репозитория.

## Code Review Rules

- Общайся с пользователем на русском языке.
- Все code review comments, включая автоматические review в GitHub и inline-комментарии к PR,
  пиши на русском языке.
- Названия типов, методов, файлов, символов и общепринятые технические термины можно оставлять
  на English, но заголовок, описание проблемы, сценарий отказа и предлагаемое исправление должны
  быть на русском.

## Обязательный контекст

Перед нетривиальной работой прочитай:

1. `.codex/project.md` — проверяемый контекст, общие инварианты и команды проекта.
2. `.codex/learning.md` — режимы обучения, реализации, ревью и исследования.

Для специализированной работы дополнительно прочитай:

- при изменении файлов в `backend/` — `.codex/backend.md`;
- при изменении файлов в `frontend/` — `.codex/frontend.md`;
- если задача затрагивает обе части — оба файла.
- при code review — `.codex/code-review.md` и правила затронутой части проекта;
- при добавлении или изменении тестов, bug fix и изменении observable behavior —
  `.codex/testing.md`;
- при работе с ветками, commits или PR — `.codex/git.md`;
- при создании или разбиении карточки задачи — `.codex/tasks.md`.

Не считай этот документ заменой изучению кода. Фактический код, тесты и конфигурация
имеют приоритет над описанием проекта.

## Выбор режима

Явно указанный пользователем режим имеет приоритет:

- `Режим: обучение` — не изменяй файлы и не выдавай полное решение до попытки пользователя.
- `Режим: реализация` — выполни изменение полностью и проверь результат.
- `Режим: ревью` — не изменяй код; сначала перечисли findings.
- `Режим: исследование` — изучи код, собери доказательства и объясни выводы без изменений.

Если режим не указан, определи его по смыслу запроса. Задавай уточняющий вопрос только тогда,
когда от выбора режима зависит изменение файлов или публичного поведения.

## Перед изменениями

- Проверь `git status` и текущий diff.
- Изучи затронутый код, ближайший похожий vertical slice и связанные тесты.
- Назови ожидаемое поведение, важные инварианты и минимальный план.
- Не изменяй несвязанные файлы и не исправляй побочные замечания без необходимости.
- Если документация противоречит коду, сообщи об этом и опирайся на проверенные факты.

## Границы действий

- Не выполняй commit, push, merge, rebase и создание PR без прямого запроса.
- Не добавляй секреты, `.env`, токены, пароли и локальные credentials в репозиторий.
- Не добавляй и не обновляй production-зависимости без текущей подтверждённой необходимости.
- Не запускай массовое форматирование или auto-fix, если оно может изменить несвязанные файлы.
- Не заявляй, что задача выполнена или тесты проходят, если соответствующая проверка не запускалась
  либо завершилась ошибкой.

## Приоритет инструкций

Прямой запрос пользователя имеет приоритет над форматом работы из этих файлов.
Специализированные файлы из `.codex/` уточняют общие правила только для соответствующей задачи.
Если инструкции конфликтуют или требуют опасного действия, остановись и запроси уточнение.
